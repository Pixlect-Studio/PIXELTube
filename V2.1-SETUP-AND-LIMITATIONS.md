# PIXELTube CODE MAX V2.1 — setup and limitations

## Added in V2.1
- Admin review queue at `#/admin/review`.
- Channel publishing mode toggle (FREE / REVIEW) in Admin → All channels.
- New uploads from REVIEW-mode channels are marked `pending` and excluded from public feeds and public watch routes until approved.
- Review decisions: APPROVE, IGNORE, DISAPPROVE (disapproval requires a reason). IGNORE leaves the video private.
- Review status and disapproval reason are shown to the creator when they open their own video.
- Moderation audit log at `#/admin/audit`, including review decisions, publishing-mode changes, and channel suspensions/reinstatements where the client can write audit data.
- Local-mode simulations for the new moderation paths.
- Existing custom domain file `CNAME` is preserved.

## Important security limitations
This is still a static frontend application. The repository has no trusted moderation backend and no Firebase Security Rules file, and its PIXLECT login identity is not shown to be backed by Firebase Authentication. Admin checks in JavaScript are not a security boundary. A technically capable user may bypass client-side moderation by writing directly to an insufficiently protected database.

The pending-video gate hides videos in the PIXELTube UI, but it cannot revoke a copied media URL or guarantee that direct database/media access is blocked. Do not treat REVIEW mode as production-private until the database and media delivery are enforced by trusted server-side code and rules.

## Bunny Stream credential safety
The supplied project contained a Bunny Stream API key in browser-fetchable configuration. V2.1 removes that key from the delivered project instead of redistributing it. **Rotate/revoke the previously exposed key in Bunny immediately.** Never place a Bunny API key in `data.env`, JavaScript, or any other file served to browsers.

Because the browser key is removed, direct Bunny Stream uploads are not configured in this package. Small uploads may use the existing Firebase base64 fallback (up to 8 MB); larger uploads need a trusted backend endpoint that holds the Bunny key server-side. Playback of existing Bunny videos can still use the CDN hostname and stored video IDs.

## Setup
1. Upload the contents of this project to your existing GitHub repository; do not deploy from this generated archive automatically.
2. Keep the root `CNAME` file and your existing custom-domain DNS setup.
3. Configure Firebase rules and a trusted backend before relying on moderation controls for security.
4. Add a server-side Bunny upload endpoint before enabling larger file uploads. Store credentials only in that backend's secret environment.
5. Test the site on your custom URL and verify console/network errors with a real account.

No live Firebase project, Bunny account, DNS record, or production browser session was accessed or modified by this build.
